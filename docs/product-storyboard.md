# The story we tell Chris

**One business case. Ready for the next conversation.**

Keep a deal’s research, assumptions, numbers and client-ready artifacts aligned as
the conversation changes. Chris retains control of the case; the software removes
repeated assembly and makes the basis of the decision easier to inspect.

## Website / demo narrative
1. Start with Chris’s situation: stakeholder priorities, new information and
   last-minute revisions arriving across a rolling deal. Show one coherent case.
2. Follow his journey: stakeholders → company branding → case inputs and evidence
   → Live Room. Introduce Files and the agent when they help that journey.
3. Show a customer workflow and a supported business impact, following Ritika’s
   structure. Explain how the inputs produce the result. Do not promise cash
   savings merely because engineering time has a monetary value.
4. Show a requirement changing status and a case input changing. Preview the
   resulting artifacts, including a carefully composed one-pager. The local room
   updates from saved inputs; publishing still requires the existing publish action.
5. Close with Chris ready for the next conversation: one case, multiple formats,
   existing evidence available privately and an editable story he controls.

## Proof and restraint
Use the polished Nike example as an illustrative scenario with clearly labeled
sample figures. Use sourced company visuals; preserve its fonts and logo. Show
actual functioning controls. Do not invent customer testimonials, time-saved
metrics, completed integrations, live synchronization or team collaboration.

The separate submission/marketing website is not implemented in this repository
(Team-tadda-project currently contains only a README and license). This storyboard
is the content handoff for that surface; the in-app waitlist copy follows it.
